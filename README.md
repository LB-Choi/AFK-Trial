# AFK Trial — 기능 구현 테스트 프로젝트

이 저장소는 정규 게임 제작물이 아니라 Unity에서 기능을 구현하고 확인하기 위한 테스트 프로젝트다. Universal 2D 기본 씬에서 실행되는 자동 전투 최소 기능과 개발 환경 설정을 포함한다. 현재는 사용자 지시에 따라 로컬에서만 작업하며 GitHub 연결·푸시는 진행하지 않는다.

## 테스트 실행

본 제작의 전투 방향은 좌우 대치다. `LOF/Assets/Scenes/SideBattle.unity`를 열고 Play하면 960×540 기준 왼쪽 아군과 오른쪽 적이 중앙으로 접근한다. 전장에서는 유닛 위치에 체력바가 표시되며, 하단의 출전 기사 초상화에서도 아군 체력을 확인할 수 있다. 기존 상하 전투 비교용 씬은 `SampleScene`이다.

1. `LOF/Assets/Scenes/SideBattle.unity`를 열고 코드 임포트가 끝날 때까지 기다린다.
2. Unity Play 버튼을 누른다. 두 전투 씬에서 실행기가 자동 생성된다. 컴포넌트를 수동으로 붙일 필요가 없다.
3. Heroes에서 영웅 카드를 누르면 해당 영웅의 능력치와 스킬 아이콘이 열린다. Back to battle을 누르면 전투 화면으로 돌아간다. Edit formation에서 목적지 슬롯을 선택하고 Apply next battle을 눌러 편성을 적용한다. 출전 중인 영웅을 다른 슬롯에 배치하면 두 영웅이 자리를 바꾼다. Cancel을 누르면 변경을 취소하고 해당 영웅의 정보창으로 돌아간다.
4. `Heroes`에서 성장시킬 영웅을 선택하고 정보창의 `Level up`을 누른다. 레벨 1에서 2로 올리는 기본 비용은 골드 20과 경험치 10이다. 두 비용 모두 선택한 영웅의 현재 레벨에 비례한다. 결제 즉시 해당 영웅의 레벨과 재화를 함께 저장하고, 새 능력치는 다음 메인 전투나 던전 전투부터 적용한다. 이전 저장 파일의 영웅별 레벨과 소환 중복 성장분도 이어진다.
5. 전장 오른쪽 위 `•••`를 열고 `Test: force defeat`로 패배·파밍 전환을 확인한다. 파밍에서 다시 패배하면 하위 단계로 이동하며 최저 연습 단계에서 멈춘다.
6. `Retry`로 원래의 다음 도전 목표에 복귀한다. 전장 하단에서 Heroes, Formation, Summon을 바로 열 수 있다. Hall의 하단 아이콘에서는 장비, 던전, 방치 보상에도 접근할 수 있다. Formation에서 슬롯과 영웅 카드를 차례로 선택하면 여러 슬롯을 한 번에 수정할 수 있다. Apply next battle을 눌러 적용한다. 일반 메뉴에서도 전투와 스테이지 전환은 계속된다. 편성·장비·영웅 레벨은 다음 전투가 시작될 때 적용되며, 현재 전투의 HP와 시너지는 유지된다.

전투 화면의 보스 진행선과 남은 시간은 진행 중인 전투를 기준으로 표시한다. Hall에서 현재 출전 중인 기사 3명과 보유 재화를 확인하고 각 화면으로 이동할 수 있다. Idle 메뉴에서는 최고 클리어 단계의 시간당 방치 보상을 확인할 수 있다.

`Hall → Dungeons`에서 Gold Vault(골드) 또는 Experience Archive(경험치)를 선택한다. 첫 회차 5스테이지 보스를 클리어하면 두 던전의 Easy가 열린다. 각 던전에서 이전 난이도를 클리어하면 Normal과 Hard가 차례로 열린다. 난이도를 선택해 예상 보상과 제한 시간을 확인하고 `Enter dungeon`을 누르면 현재 편성으로 자동 전투를 시작한다.

승리하면 해당 던전의 재화를 즉시 지급한다. 패배하거나 `Retreat`로 나왔을 때의 획득량은 0이다. 결과 팝업은 원래 도전 중이거나 파밍하던 메인 스테이지 위에 표시된다. `Resume battle`을 누르면 해당 메인 전투가 처음부터 진행된다.

게임을 종료하면 UTC 시각과 진행도를 로컬에 저장한다. 다시 접속해 받을 보상이 있으면 Welcome back 창에서 부재 시간, 기준 스테이지, 골드와 경험치를 확인한다. Confirm & collect를 누를 때 재화와 장비를 함께 지급한다. 첫 스테이지 클리어 후에는 유효 방치 시간에 효율을 적용한 가상 승리 횟수만큼 장비도 추첨한다. 최고 클리어 단계가 일반이면 5%, 보스면 10%이며, 종류별 10개를 초과한 장비는 골드로 전환해 지급액에 합산한다. 확인 전에 게임을 종료하면 다음 접속까지 미수령 시간이 이월된다. 팝업을 보고 있는 시간은 적립에서 제외한다.

방치 보상은 종료 당시 최고 클리어 단계의 일반 승리 보상을 기준으로 계산한다. 첫 클리어 전에는 연습 단계 보상을 사용한다. 기본 설정은 30초당 일반 승리 1회, 효율 80%, 누적 최대 20시간이며 재화별 소수점은 버린다. 진행도는 Unity 사용자 저장 폴더의 `AFKTrial/progress.json`에 기록하며, 전투 도중 종료하면 재접속 시 저장된 스테이지에서 전투를 새로 시작한다.

현재 포함: 캐릭터 10종과 3인 편성, 3대3 기본 공격, 최근접 대상 선택·사망까지 유지, 자동 이동, HP·공격 간격, 제한 시간, 동시 전멸 패배, 5단계마다 보스, 회차 표시, 일반/최초 재화 보상, 파밍, 성장·재도전.

같은 역할 두 명을 편성하면 맹공(공격력 +10%), 수호(받는 피해 −10%), 강화(공격력·최대 HP +5%) 중 하나가 적용된다. 편성창은 현재 시너지와 변경 후 시너지를 함께 표시한다.

영웅 정보창 왼쪽에서 무기·갑옷·목걸이를 각각 선택해 장착하거나 해제한다. 교체한 장비는 가방으로 돌아온다. 메인 전투 승리 시 일반전은 5%, 보스전은 10% 확률로 +0 장비를 얻는다. 유형별로 장착분을 포함해 10개까지 보유하며 초과 획득분은 판매가만큼 골드로 전환한다. 가방과 장착창의 Enhance 버튼은 선택한 장비 한 개를 확정 강화한다. 기본 비용은 다음 강화 단계 × 20골드이며, 강화 상한은 최고 도달 회차 +10이다. 무기는 단계당 공격력 1, 갑옷은 방어력 2, 목걸이는 최대 HP 5가 추가된다. 영웅 정보창에는 장착 효과가 즉시 표시되고 전투에는 다음 전투부터 적용된다. Gear에서 미장착 장비를 골드로 판매할 수 있다.

영웅별 세 스킬은 메인·던전 전투에서 자동 발동한다. 첫 슬롯은 기본 공격 횟수, 나머지 두 슬롯은 경과 시간으로 충전한다. 영웅 정보창에서 발동 조건과 효과를 확인할 수 있다. 스킬 레벨은 전투 시작 시 적용되며 발동한 스킬 이름은 영웅 위에 표시된다.

### Hall에서 스테이지 반복하기

`Hall → Repeat stage`에서 한 라운드의 10개 스테이지를 가로·세로 화면 모두 5열 × 2행으로 확인한다. 화살표로 라운드를 옮기고, 클리어한 일반 또는 보스 스테이지를 골라 `Set repeat`를 누른다. 미클리어 단계에는 `Locked`가 표시된다. 현재 전투가 끝난 뒤부터 목표를 반복하며, 승리 시 해당 단계의 일반 골드·경험치를 받는다. 패배해도 같은 단계를 다시 시도한다. 반복 설정은 재접속 후에도 유지된다. `Stop repeating`을 누르면 다음 메인 전투부터 기존 도전이나 자동 파밍으로 돌아간다.

## 게임 데이터 수정

원본 테이블은 `LOF/Assets/StreamingAssets/Data`에 있다. Excel에서 첫 행의 열 이름을 유지하고 **CSV UTF-8(쉼표로 분리)** 형식으로 저장한 뒤 Unity Play를 다시 시작하면 적용된다. 소수점은 마침표를 쓴다. Windows 빌드에서 수치만 시험할 때는 `AFK-Trial_Data/StreamingAssets/Data`의 복사본을 수정하고 게임을 다시 실행한다. 다음 빌드에도 유지할 변경은 프로젝트 원본에 반영한다.

| 파일 | 조정 항목 |
| --- | --- |
| Summoning.csv | 시작 소환권과 최초 클리어 보상. startWithAllHeroes는 테스트 시 1, 시작 편성 3명만 보유할 때 0 |
| Skills.csv | heroId와 slot(1~3)별 이름·설명·강화 기본 골드 비용. 설명에 쉼표가 있으면 CSV 따옴표로 감싼다. |
| Equipment.csv | 새 게임에서 지급하는 장비 한 개당 한 행. 종류, 이름, 기본 능력치, 판매 가격, 강화 단계당 증가량(bonusPerEnhancement) |
| IdleRewards.csv | 방치 시간 상한(`capHours`), 온라인 기준 효율(`efficiencyPercent`), 일반 승리 한 번의 기준 시간(`referenceClearSeconds`) |
| Dungeons.csv | 던전 종류(`kind`)와 난이도(`tier` 1~3)별 적 능력치 배율(`power`), 제한 시간(`seconds`), 승리 시 지급할 재화량(`reward`) |
| Heroes.csv | 역할(role: Attack, Defense, Support), 캐릭터별 이름, 초상화, 애니메이션, 기본 HP·공격력, 레벨당 증가량, 기본 방어력(baseArmor)과 레벨당 방어력(armorPerLevel), 이동 속도, 사거리, 공격 주기(초), 초기 편성 |
| Enemies.csv | 일반 적과 보스의 이름, 기본 HP·공격력, 이동 속도, 사거리, 공격 주기(초) |
| Progression.csv | 보스 등장 간격과 위치, 회차 길이, 제한 시간, 적 스탯 배율, 보상, 영웅 레벨당 골드·경험치 비용, 배치 간격, 전투 재시작 대기 시간 |
| Animations.csv | 캐릭터 애니메이션 리소스와 기본 공격의 타격 시간(초). Heroes.csv의 animation 열에서 ID를 지정한다. |
| HitFlash.csv | 타격 시트의 Resources 경로, 가로·세로 칸 수, 사용할 프레임 수, 초당 프레임, 가로·세로 화면에서의 표시 크기 |

예를 들어 Heroes.csv의 `ice_knight` 행에서 `hp`를 120, `attack`을 18로 저장하면 1레벨 얼음검 기사가 HP 120, 공격력 18로 시작한다. `startingSlot` 1~3은 각각 한 명에게 지정하고 대기 캐릭터는 0으로 둔다. 이름을 변경해도 리소스·애니메이션 연결은 유지된다. 스테이지의 적 배율은 기본 배율에 스테이지 번호와 단계당 증가량의 곱을 더한 값이다. 연습 스테이지에는 별도 배율을 적용한다.

신규 콘텐츠의 조정 가능한 게임 수치도 CSV에 추가한다. 개발 완료 시 테이블별 시트를 담은 Excel 파일을 출력하고, 각 시트를 같은 이름의 CSV로 저장해 게임에 반영한다.

타격 효과는 [ParticleFX Studio의 Hit Flash](https://particlefx.studio/effects/hit-flash) 무료 PNG 출력에서 예시 캐릭터를 제외하고 첫 번째 타격을 추출했다. 피해를 받은 유닛의 위치에서 한 번 재생한다.

### 확인 결과와 재실행

- Unity 6000.5.0f1에서 컴파일 후 모델 검사가 통과했다. 첫 승리·보상 중복 방지·성장 반영·파밍·후퇴·최저 단계·재도전·동시 전멸·재화 부족·회차 표기를 검사한다.
- `AFK Trial > Run Model Checks` 메뉴로 다시 실행할 수 있다. 상세 결과는 로컬 `LOF/Logs/TrialChecks.txt`에 기록한다. Logs는 Git 제외 대상이다.
- Editor 코드 재로드 때는 실제 CSV 구성을 검사한다. 메뉴에서 실행하는 모델 회귀 검사는 고정된 테스트용 데이터로 기존 전투 규칙을 확인한다.
- 장비·던전·방치 보상과 라운드별 반복 설정을 개편한 Windows 버전은 `LOF/Builds/CourtExpedition/AFK-Trial.exe`로 실행한다. 다른 PC로 옮길 때는 `CourtExpedition` 폴더 전체를 복사한다. 이전 기사단 UI 버전은 `LOF/Builds/KnightCourt`에 있다. `Builds`는 Git 제외 폴더다.
- 이전 가로 전투 테스트 빌드는 `output/LandscapeTest/AFK-Trial.exe`에 있다. 당시 960×540 창에서 확인한 첫 스테이지와 양측 체력 패널은 편성창 추가 이전 캡처인 `output/LandscapePreview.png`에서 볼 수 있다.

## 환경

- Unity: **6000.5.0f1** (프로젝트 버전 파일 기준)
- 프로젝트: 저장소 루트의 `LOF` 폴더, Universal 2D / URP
- IDE: Visual Studio 2022 또는 VS Code. IDE 선택은 각 PC의 Unity Preferences에서 설정한다.
- 테스트 출력: Windows, 가로 16:9. 기본 창 960×540, 크기 변경 허용.
- 현재 PC: RAM 32 GB / NVIDIA GeForce RTX 5070 Ti. 최소 요구 사양이나 고정 개발 조건이 아니다.
- 사용자 이름이나 `C:/Users/User`를 코드에 고정하지 않는다.

## 다른 PC에서 이어서 작업하기

1. GitHub 저장소를 복제하거나 작업 시작 전에 최신 커밋을 가져온다.
2. Unity Hub에서 정확히 `6000.5.0f1`을 설치하고 로그인·라이선스 활성화를 완료한다.
3. Hub에 `LOF` 폴더를 추가해 연다. `Library`와 패키지 캐시는 자동 재생성되며 인터넷이 필요할 수 있다.
4. 첫 임포트가 완료되면 Editor 전용 스크립트가 테스트 창 설정을 적용한다. Console의 `[AFK Trial] Test setup applied` 메시지로 확인한다. 수동 재적용 메뉴는 `AFK Trial > Apply Test Project Settings`다.
5. Game 뷰 비율은 각 PC에서 16:9로 선택한다. Windows 창 설정은 Game 뷰 비율을 자동 변경하지 않는다.
6. `HANDOFF.md`의 최신 상태를 확인하고 다음 작업을 이어간다.

선택: 저장소 루트에서 `powershell -File ./tools/Open-Unity.ps1`로 프로젝트를 열 수 있다. Unity가 다른 위치에 설치되어 있으면 `-EditorPath "D:/.../Unity.exe"`를 전달한다. 설치 버전 자체는 Hub에서 확인한다.

## Git 보관 기준

- 보관: `LOF/Assets`와 `.meta`, `LOF/Packages`의 manifest와 lock, `LOF/ProjectSettings`, 문서와 도구.
- 제외: Library, Temp, Logs, UserSettings, IDE 캐시, 생성된 솔루션과 빌드 출력.
- `.meta`와 해당 리소스는 함께 이동·커밋한다.
- 라이선스·인증 토큰은 저장소에 넣지 않는다. 로그인은 새 PC에서 진행한다.
- 현재 별도 대용량 아트가 없어 Git LFS는 적용하지 않았다. 추후 리소스 추가 전 용량을 확인한다.
- 플레이 세이브는 소스 관리 대상이 아니다. 별도 백업이 필요하면 정책을 정한다.

## 매일 작업 종료

1. Unity의 씬과 프로젝트 변경을 저장한다.
2. `git status --short`와 diff에서 변경을 확인한다.
3. 필요한 소스·설정·기록을 커밋한다.
4. 연결된 GitHub 원격에 푸시하고 성공 여부를 확인한다. 로컬 커밋만으로는 PC 초기화에 대비할 수 없다.
5. HANDOFF에 구현 범위, 실제 확인 결과, 남은 문제와 다음 시작점을 기록한다.

현재 원격 주소는 미연결이다. 사용자가 로컬 작업을 선택했으므로 원격 연결이나 업로드를 대기 작업으로 취급하지 않는다. PC 초기화 전 보존이 필요하면 별도 백업을 진행해야 한다.

## 테스트 개발 범위

스킬 효과와 전투 수치는 테스트용 밸런스다.

Editor 설정 스크립트는 첫 임포트 시 `Library/AFKTrialSetup-v2.txt`에 실행 기록을 남긴다. Library를 재생성하면 테스트 설정이 다시 적용된다. `runInBackground=false`는 전체 최소화·방치 시스템의 구현을 대신하지 않는다.
